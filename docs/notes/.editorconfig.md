# 2. EditorConfig

> **Purpose**
>
> Configure the editor—not the code. EditorConfig ensures every developer's editor follows the same basic rules, resulting in consistent files regardless of the IDE or operating system.

---

# Why Use EditorConfig?

Different developers use different editors and operating systems.

Without EditorConfig, the same file may be saved differently by each editor, creating unnecessary Git changes and inconsistent formatting.

EditorConfig solves this by defining common editor behavior for the entire project.

---

# What Problems Does It Solve?

Without EditorConfig:

- Different indentation (Tabs vs Spaces)
- Different line endings (CRLF vs LF)
- Different file encodings
- Missing final newline
- Trailing whitespace
- Large, meaningless Git diffs

---

# Project Decision

| Setting | Value |
|----------|-------|
| Character Encoding | UTF-8 |
| Line Ending | LF |
| Indentation | 2 Spaces |
| Final Newline | Enabled |
| Trim Trailing Whitespace | Enabled |
| Markdown Exception | Preserve trailing spaces |

Create the following file in the project root.

```text
.editorconfig
```

# Project Configuration

```ini
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

---

# Configuration Breakdown

## root = true

```ini
root = true
```

### Purpose

Stops EditorConfig from searching parent directories for another `.editorconfig`.

### Why?

Ensures this project uses only its own configuration.

---

## [*]

```ini
[*]
```

### Purpose

Apply the following rules to every file.

---

## charset = utf-8

```ini
charset = utf-8
```

### Purpose

Save every file using UTF-8 encoding.

### Why?

- Universal encoding
- Supports all languages
- Prevents strange characters
- Standard for modern development

---

## end_of_line = lf

```ini
end_of_line = lf
```

### Purpose

Use LF (`\n`) for every file.

### Why?

Windows

```text
CRLF
```

Linux / macOS

```text
LF
```

Git repositories generally use **LF**.

Using LF prevents unnecessary line-ending changes across operating systems.

---

## indent_style = space

```ini
indent_style = space
```

### Purpose

Use spaces instead of tabs.

### Why?

Tabs may display differently depending on editor settings.

Spaces provide consistent indentation everywhere.

---

## indent_size = 2

```ini
indent_size = 2
```

### Purpose

Every indentation level uses **2 spaces**.

### Example

Correct

```ts
function greet() {
  console.log('Hello');
}
```

Avoid

```ts
function greet() {
        console.log('Hello');
}
```

---

## insert_final_newline = true

```ini
insert_final_newline = true
```

### Purpose

Automatically add a newline at the end of every file.

### Why?

- POSIX recommendation
- Better Git compatibility
- Cleaner file handling
- Prevents "No newline at end of file" warnings

---

## trim_trailing_whitespace = true

```ini
trim_trailing_whitespace = true
```

### Purpose

Remove unnecessary spaces at the end of each line.

### Example

Incorrect

```text
const name = 'Roko';····
```

Correct

```text
const name = 'Roko';
```

Trailing spaces add noise to Git history without providing any value.

---

## Markdown Exception

```ini
[*.md]
trim_trailing_whitespace = false
```

### Purpose

Do not remove trailing spaces from Markdown files.

### Why?

Markdown uses two trailing spaces to create a line break.

Removing them can change how documentation is rendered.

# Implementation (Step-by-Step)

## Step 1 — Create the File

At the project root, create:

```text
.editorconfig
```

---

## Step 2 — Paste the Configuration

```ini
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2

trim_trailing_whitespace = true
```

---

## Step 3 — Install EditorConfig Extension (Optional)

Although many modern editors support EditorConfig by default, install the extension if your editor requires it.

For VS Code:

Search

```text
EditorConfig for VS Code
```

Install the official extension if needed.

---

## Step 4 — Restart the Editor

Reload or reopen the project so the editor applies the new configuration.

---

## Step 5 — Verify

Create a new file.

Press **Tab**.

Expected:

```text
2 Spaces
```

Not

```text
Tab Character
```

Save the file.

Verify:

- UTF-8 encoding
- LF line endings
- Final newline exists
- No trailing whitespace

# EditorConfig vs Prettier

| EditorConfig | Prettier |
|--------------|----------|
| Configures the editor | Formats code |
| Controls file behavior | Controls code style |
| Runs when editing/saving | Runs during formatting |
| Handles encoding, line endings, indentation | Handles quotes, semicolons, commas, wrapping |

**Remember:**

EditorConfig and Prettier work together.

EditorConfig does **not** replace Prettier.

---

# Common Mistakes

### Forgetting `root = true`

The editor may inherit another `.editorconfig` from a parent folder.

---

### Using CRLF

Creates unnecessary Git diffs when collaborating across operating systems.

---

### Using Tabs

Different editors display tabs differently.

Use spaces for consistent formatting.

---

### Removing the Markdown Exception

Trailing spaces used for Markdown line breaks will be removed, changing rendered documentation.

---

# Best Practices

- Keep only one `.editorconfig` at the project root.
- Use LF for all Git repositories.
- Prefer spaces over tabs.
- Keep indentation consistent across the project.
- Let the editor apply these rules automatically.

---

# Quick Revision

- EditorConfig configures the **editor**, not the code.
- Prevents editor-specific inconsistencies.
- Uses UTF-8, LF, 2-space indentation, final newline, and trimmed trailing whitespace.
- Markdown files keep trailing spaces to preserve formatting.
- Always create `.editorconfig` before writing project code.
